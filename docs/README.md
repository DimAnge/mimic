# The Mimic site

`index.html` is the whole site: one file, no build step, no dependencies beyond
two web fonts. Open it in a browser to work on it.

## Publishing

Either way works. Pick one.

**Branch setting (simplest).** Settings → Pages → Source: *Deploy from a branch*
→ branch `main`, folder `/docs`. Push, wait a minute, done.

**Actions workflow.** Settings → Pages → Source: *GitHub Actions*. The workflow
in `.github/workflows/pages.yml` then publishes `docs/` on every push to `main`.

`.nojekyll` is there so GitHub serves the folder as-is.

## Before the first push

Replace `DimAnge` in these places:

- `docs/index.html` — the `og:url` and `og:image` tags, three GitHub links
- `README.md` — the site link and the footer link

Then set the social image: Settings → General → Social preview → upload
`docs/assets/social-preview.png`.

The current identity is the bracket mark: a face held in square brackets, one
ink, no bezel and no glow. It is generated by `tools/make_bracket_assets.py`.

Everything is generated geometry — no fonts are needed to render the logos, so
they survive being embedded anywhere.

To go back to the first identity, copy `classic/` over the top:

```bash
cp docs/assets/classic/* docs/assets/
```

Regenerate after editing the scripts in `tools/`:

```bash
pip install cairosvg
python3 tools/make_assets.py
python3 tools/make_wiring.py
python3 tools/make_bracket_assets.py   # the current logo set
python3 tools/make_alt_logos.py        # the directions not chosen
```

## Real screenshots

`screenshot.py` on the board prints the framebuffer over USB serial; `tools/shot.py`
turns that into a PNG in this palette.

```bash
python3 tools/shot.py /dev/ttyACM0 --bezel        # live, press "s" in the console
python3 tools/shot.py --paste dump.txt --bezel    # from a saved console dump
```

Dumps land in `docs/assets/shots/`. Rebuild the contact sheet from them with:

```bash
python3 tools/make_sheet.py FACE=docs/assets/shots/face.png \
  CALENDAR=docs/assets/shots/calendar.png SPOTIFY=docs/assets/shots/spotify.png \
  SYSTEM=docs/assets/shots/system.png DINO=docs/assets/shots/dino.png \
  "8 BALL=docs/assets/shots/eightball.png"
```

## Colours

| Token | Hex | Where |
| --- | --- | --- |
| Paper | `#E7E9E6` | Page background |
| Ink | `#16181A` | Text, the case |
| Ink 2 | `#5B6166` | Secondary text |
| Rule | `#C9CDC8` | Hairlines |
| Screen | `#080A0C` | Inside the bezel |
| Glow | `#BFE3FF` | Lit pixels |

Colour is only used where it carries information: the wire map uses red for 3V3,
dark grey for ground, blue for I2C data, yellow for I2C clock, green for button
inputs and purple for the buzzer signal. Everything else is 1-bit, like the
device.

## The simulator

The device in the hero is a real 128×64 framebuffer. Each screen draws white
shapes and text onto an off-screen canvas, then every pixel is thresholded to on
or off before being scaled up — which is why the type looks like the real display
rather than smooth browser text.

To add a screen, add an entry to the `SCREENS` array with a `draw` function and
handle it in `b2Tap`. The tab dots and the list further down the page build
themselves from that array.
